# Caption evidence for provisional comparisons

The existing API key collector provides public metadata. It does not retrieve captions or watch videos. YouTube's official caption download requires an authorized user with permission to edit the video: https://developers.google.com/youtube/v3/docs/captions/download . The private workspace now attempts experimental public retrieval through youtube-transcript-api 1.2.4 when preparing a comparison. This unofficial source can fail or be blocked; official owner-authorized integration remains future work.

The private web workspace accepts a batch of SRT, VTT or TXT captions, matched to known inventory IDs in filenames. Processing is entirely in the browser; captions are not uploaded, persisted, used for training or sent to an AI provider. Limits: 100 files, 2 MB combined, 200,000 characters per video. Invalid/duplicate/unknown IDs reject the batch. Removing captions, changing channel or reloading clears the evidence. Every imported caption is creator supplied and unverified.

Preparation ignores titles, view counts and durations. It preserves Unicode combining marks, normalizes text to NFC, removes timing/tag lines and repeated caption lines, screens exact five-word overlap, and compares weighted shared vocabulary. Eligible uploads require at least 40 remaining words and 168 hours of publication age. At least four shared vocabulary terms and cosine similarity >=0.15 are setup heuristics. >=65% overlap relative to the smaller set of five-word sequences, with at least ten sequences, screens a possible related upload out, keeping the newer one. This may exclude repeated scripts and does not establish reused footage. The proposal scans caption references in publication order, preferring the first reference with three matching recent and three strictly older uploads. If none exists, it offers the first reference with three recent and two strictly older matches, visibly labeled as a small sample; the reference itself need not be the newest match; it may leave out newer unmatched uploads. The evidence expander lists shared words so the selection can be inspected.

These thresholds are uncalibrated. Shared wording is lexical evidence, not semantic understanding. Different vocabulary, multilingual translations, sparse captions, generic discussions, inaccurate captions and repeated scripts can produce false matches or missed matches. Topics, Shorts/long-form/live formats, audience intent and footage independence remain unverified. Titles and duration cannot supply missing proof. No automatic creator comparability assertion is set. If caption evidence is insufficient, the content path abstains rather than silently reverting to date-only groups. A creator can remove captions to explicitly use the existing date-only setup.

This is a working evidence-input and provisional grouping path, not complete automatic public-channel diagnosis. Owner-authorized acquisition, format evidence, question/scope interpretation and evaluation on independently reviewed real examples remain necessary before stronger claims or default autonomous grouping.

Validation includes title/view invariance, timing parsing, empty/short/boilerplate abstention, text overlap, unrelated text, time boundaries and invalid provenance. Browser CI covers batch import, invalid filenames, explanation, removal and accessibility at four viewport widths using synthetic fixtures. These tests establish implementation behavior, not real-world grouping accuracy.

## Automatic public retrieval pilot

Preparing groups without supplied captions requests the twelve newest inventory uploads at least 168 hours old. The authenticated development-only bridge accepts IDs, never arbitrary URLs. The server lists available tracks and retrieves one sequentially with a 30-second start budget, at most four seconds per underlying HTTP request, and no retries/proxies/cookie login/block bypass. A blocked response stops remaining requests. Each transcript retains video identity, language, generated-caption flag and timestamped segments; text is capped at 200,000 characters and 10,000 segments. English is preferred, then an available manual track, then a generated track in stable language order. No translation is requested. The returned language code is preserved; known different languages do not enter the same shared-word group. Empty, missing, timeout, blocked, oversize and failure statuses are distinct. Exception details are withheld.

If no captions arrive, the interface clearly labels its date-only fallback. If some arrive but do not support two groups, the caption path abstains. Retrieved captions are marked public_caption_unverified and stay in the current page; they are not saved in Creator Memory. They are not ground-truth speech or proof of footage independence. External retrieval is not called by metadata collection or CI fixtures.

A live retrieval check on 2026-10-05 obtained 105 segments for EiKq-iUjHVw; two preceding Matt Rife requests timed out. This demonstrates access, not consistent coverage or grouping accuracy. No fair-comparison benchmark has yet been established from independently reviewed real videos. Browser CI separately tests mocked success and blocked fallback, without treating synthetic fixtures as live evidence.

## Investigation after the 11-caption pilot

The creator's pasted result reported 11 available captions, one overlap exclusion and no groups. It did not include the caption text or full timestamps, so its exact failed checks cannot be reconstructed from the paste alone.

Removed an extra reference-order constraint that required the anchor itself to be the newest matching upload. A regression fixture demonstrates that an older reference can match newer and older uploads while the newest individual caption lacks enough matches. Similarity, word-count, overlap and chronology thresholds remain unchanged. This fixes a selection restriction, not semantic understanding. A broad reference can also match otherwise different discussions; all proposals remain provisional and the reference is shown in the explanation.

A fresh eight-ID subset of the Matt Rife sample returned seven captions and one timeout. Using displayed calendar dates as approximate timestamps, both the previous and revised matcher abstained. Diagnostics found seven usable captions, no overlap exclusions in this subset, a largest shared-word set of four uploads and at most one strictly older match after selecting three recent uploads. This is a partial investigation, not an exact reproduction of the creator's eleven-caption session. No threshold was lowered to manufacture groups.

The workspace now separates automatically retrieved captions from supplied files and exposes remaining distinct uploads, largest match-set size and the best strictly older count when no proposal is possible. These counts explain deterministic rejection; they do not show that videos are unrelated.

## Content evidence improvement — 2026-10-06

English-only retrieval was an avoidable coverage restriction; unavailable English tracks do not show that Hindi or other-language captions are absent. Track selection now uses the installed youtube-transcript-api 1.2.4 list/track.fetch API (see https://github.com/jdepoix/youtube-transcript-api). Provider results preserve language and generation provenance, request no translations, and keep existing timeout, size and block-stop limits. The interface shows returned language codes. Matching separates different known primary language codes; supplied files with unknown language remain unverified. Unicode combining marks stay attached to words. This enables evidence input; it does not validate multilingual semantic matching, stopwords, topic identity or transcript accuracy. Real Be YouNick coverage has not been verified.

Selected video durations are now measured from the API's ISO duration strings. A provisional review flag appears when the longest measured selection is at least five minutes and at least four times the shortest. The screen shows the actual range and directs review; it does not classify Shorts, livestreams or full shows, and does not establish a cause. Unknown/zero/malformed durations remain unavailable. Source-linked duration evidence and coverage sit in report details. Explicit requested groups are preserved; flags do not replace their videos. Entered equal-window analytics retain the duration comparability concern. These thresholds are review defaults, not validated fairness criteria.

### Small-group fallback (2026-10-06)

Caption preparation prefers three recent and three strictly older matches across all candidate references. If no complete comparison exists, it can offer three recent and two strictly older matches for review. Fewer than five qualifying uploads still abstains. Language, shared-word, overlap and seven-day rules are unchanged. Prepared groups and results visibly label the small sample; no reliability threshold or verified content match is claimed. Excluded-upload counts use the actual selection size.


Automatic proposals with the existing large-duration-spread flag now require review before comparison. A direct review action opens only selected videos. The creator can adjust the groups or explicitly keep the differing lengths; changing the selection clears that acknowledgment. This never asserts format or content comparability and preserves explicit requested groups.


### Caption-unavailable length fallback (2026-10-06)

When no captions are retrieved and default date groups trigger the existing duration review flag, preparation can use measured durations and publication dates. It searches ranges with a longest/shortest ratio strictly below four, excludes unknown durations, retains the seven-day age cutoff and strict recent/earlier chronology, and prefers 3+3 over 3+2. Among equal-sized proposals it favors newer recent groups deterministically. Titles and views never drive selection. The screen labels this date-and-length fallback, exposes excluded counts and the selection reason, and keeps all content/format/footage assertions unknown. Explicit upload scopes and partial-but-insufficient caption evidence never take this fallback. If no measured proposal is possible, existing date groups retain the review requirement. These heuristics are not validated content matching.
